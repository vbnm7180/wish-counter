# Заметки по Rust в этом проекте

Краткие пояснения к конструкциям, которые встречаются в коде, со ссылками на примеры.
Для систематического изучения рекомендуется официальная книга «The Rust Programming Language»
(есть русский перевод: «Язык программирования Rust»).

## Крейты и модули
- По умолчанию `mod game;` ищет файл `game.rs` или `game/mod.rs`. Атрибут `#[path = "game/game.rs"]`
  указывает файл явно. Так в проекте подключены модули с тестами (ADR-009).
- **Крейт** — единица компиляции (библиотека или программа). У каждого крейта свой `Cargo.toml`.
- **Модуль** — файл или папка внутри крейта: `mod game;` подключает `game.rs`, папка подключается через `mod.rs`.
- `pub` делает элемент видимым снаружи модуля. `pub use` реэкспортирует его (пример: `application/src/ports/mod.rs`).

## Владение и заимствование
- `&str` — заимствованная строка (только чтение), `String` — строка, которой владеют.
  `GameId::as_str(&self) -> &str` отдаёт ссылку без копирования.
- `impl Into<String>` в аргументе принимает и `&str`, и `String` (`GameId::new`).

## Обработка ошибок
- Ошибки возвращаются как `Result<T, E>`, исключений в Rust нет.
- Оператор `?` возвращает ошибку из функции досрочно и при этом преобразует её через `From`
  (пример: `bootstrap::run`, `commands::settings`).
- `thiserror` генерирует реализацию ошибок по атрибутам `#[error(...)]` и `#[from]`.
- `Option<T>` — «значение или ничего» (`GameCatalog::find`).

## Трейты
- **Трейт** — интерфейс: набор методов, которые тип обязуется реализовать (`GameModule`, `SettingsRepository`).
- `dyn Trait` — «любой тип, реализующий трейт», выбор происходит во время выполнения.
- `Arc<T>` — указатель с подсчётом ссылок, который можно разделять между потоками.
- `Send + Sync` — объект можно передавать и разделять между потоками.

## derive и serde
- `#[derive(Debug, Clone, ...)]` генерирует стандартные реализации автоматически.
- `Serialize/Deserialize` (serde) — преобразование в JSON и обратно.
  `#[serde(transparent)]`, `#[serde(try_from = "String")]`, `#[serde(default)]` — см. `domain/src/settings.rs`.

## Приёмы из расчёта гаранта (этап 2)
- **Время жизни** `'a` в `PityTracker<'a>` (`domain/src/pity/tracker/tracker.rs`) — трекер хранит ссылки
  на правила и не может жить дольше них. Компилятор проверяет это сам.
- `std::mem::take(&mut x)` возвращает значение и записывает на его место значение по умолчанию (для чисел 0).
  Так «забрать счётчик и обнулить» записывается одной операцией.
- `const fn` можно вызывать при компиляции: `const CHARACTER: BannerCode = BannerCode::new(301);`.
  `assert!` внутри `const fn` превращает ошибку в константе в ошибку компиляции (`Probability::from_basis_points`).
- `impl IntoIterator<Item = &'w Wish>` в аргументе принимает и срез, и итератор с фильтром, без копирования молитв
  (`calculate_pool_statistics`).
- `Option` + `?`: `self.rules.fifty_fifty.as_ref()?;` — если правила нет, функция сразу возвращает `None`.
- `match (a, b) { (true, true) => ..., (false, _) => ... }` — сопоставление сразу по двум значениям (`FiftyFiftyState::apply`).
- **serde:** `#[serde(tag = "state")]` добавляет поле-метку варианта enum; `#[serde(flatten)]` раскрывает вложенную
  структуру в родительскую; `#[serde(into = "u8", try_from = "u8")]` — `Rarity` в JSON выглядит как число.

## Приёмы из работы с SQLite (этап 3)
- `Mutex<Connection>` (`sqlite_wish_repository.rs`) — только один поток за раз получает доступ к соединению.
  `lock()` возвращает «охранника» (`MutexGuard`), и блокировка снимается, когда он выходит из области видимости.
- **Блок `{ ... }` для заимствований:** в `add_wishes` подготовленный запрос заимствует транзакцию.
  Он должен «умереть» до `transaction.commit()`, поэтому объявлен во внутреннем блоке.
- `include_str!("файл")` встраивает текст файла в программу при компиляции (SQL миграций).
- Двухшаговое чтение: сначала строка таблицы читается в «сырую» структуру `StoredWish`, затем проверяется
  в `into_wish()`. Ошибка данных возвращается как `Result`, а не вызывает панику.
- `collect()` в `Result<Vec<_>, _>` останавливается на первой ошибке и возвращает её (`list_wishes`).
- Папка `tests/` крейта — интеграционные тесты: каждый файл собирается как отдельная программа.

## Приёмы из разбора данных (этап 4a-1)
- **Рекурсивный спуск** (`paimon/js_literal/js_literal.rs`): у каждой конструкции (объект, массив, строка) своя
  функция; `parse_value` по первому символу решает, какую вызвать. Объект содержит значения, поэтому `parse_object`
  снова вызывает `parse_value` — это и есть рекурсия.
- **Указатель на функцию** `fn(&mut Self) -> Result<...>` в `Parser::nested` позволяет передать «какой метод
  вызвать» как обычный аргумент.
- `enum` с данными (`JsValue::Object(Vec<(String, JsValue)>)`) — рекурсивный тип, который хранит дерево значений.
- `let Ok(x) = ... else { return ... };` (let-else) — «разобрать или выйти» (`convert_item`).
- `iter_mut()` + `*id = ...` — изменение элементов коллекции на месте (`align_banner_ids`).
- `BTreeSet` — множество, которое хранит элементы отсортированными и без повторов (`find_unknown_ids`).
- `env!("CARGO_MANIFEST_DIR")` и `concat!` — макросы, которые подставляют значения при компиляции
  (`data-sync`, `USER_AGENT` в `http_client.rs`).

## Приёмы из этапа 4a-2
- `Box<dyn Trait>` (`build_featured_lookup` в `statistics_service.rs`) — функция возвращает объекты **разных** типов
  (`ScheduleFeaturedLookup` или `NoFeaturedData`) через один тип результата. Объект живёт в куче.
- `Option::transpose()` превращает `Option<Result<T, E>>` в `Result<Option<T>, E>` (`SqliteProfileRepository::server_region`).
- `OptionalExtension::optional()` из rusqlite: «строк нет» становится `Ok(None)`, а не ошибкой.
- `chrono::NaiveDateTime` — дата и время без часового пояса; `+ Duration::hours(..)` — арифметика (`schedule_lookup.rs`).
- `HashSet` — множество для быстрой проверки «есть ли предмет в списке» (`BannerWindow`).
- `Arc::clone(&x)` и `x.clone()` для `Arc` делают одно и то же: копируют указатель, а не данные.
  Первая запись подчёркивает, что копируется именно указатель (`bootstrap.rs`).

## Приёмы из этапа 4b
- **Метод трейта с реализацией по умолчанию** (`GameModule::remote_reference` возвращает `None`): типы, которым
  это не нужно, ничего не пишут.
- `RwLock` (`ReferenceService`) — много читателей одновременно или один писатель. `unwrap_or_else(PoisonError::into_inner)`
  берёт данные даже после паники другого потока, если они заведомо целые.
- `Mutex<()>` как «замок без данных» (`ReferenceUpdater::update_lock`): не даёт двум обновлениям идти одновременно.
- `std::thread::Builder::new().name(..).spawn(move || ..)` — именованный фоновый поток (`background.rs`).
- **async-команда Tauri + `spawn_blocking`** (`commands/reference.rs`): долгая блокирующая работа уходит в отдельный поток.
  `.await??` — первый `?` для ошибки запуска потока, второй — для ошибки самой работы.
- `T: DeserializeOwned` в `read_json` — обобщённая функция для любого типа, который serde умеет прочитать.
- `#[ignore]` у теста — пропускается обычным `cargo test`, запускается с `-- --ignored`.

## Приёмы из этапа 4c
- **Собственный протокол Tauri** (`register_asynchronous_uri_scheme_protocol` в `bootstrap.rs`): замыкание получает
  запрос и «ответчик» (`UriSchemeResponder`); ответить можно позже, из другого потока (`image_protocol.rs`).
- `bool::then(|| ...)` — превращает условие в `Option`: `valid.then(|| значение)` (`parse_image_path`).
- `starts_with(&PNG_SIGNATURE)` — проверка «магических байт» формата файла.
- Одна структура реализует два трейта (`GitHubReferenceDownloader`: `ReferenceDownloader` и `ImageDownloader`),
  а один `Arc` передаётся туда, где ожидается `Arc<dyn ...>` любого из них.
- Сырые строки `r"a\b"` — обратная косая черта без экранирования (тест `safe_file_stems`).

## Приёмы из этапа 5a
- **Сопоставление со срезом** (`parse_image_path`): `match parts.as_slice() { [ITEMS_ROUTE, game, item] if ... => ... }` —
  разбирает путь сразу по количеству и содержимому частей; константы в образце сравниваются со значением.
- `&'static [u8]` (`GameModule::icon_png`) — ссылка на байты, которые существуют всё время работы программы
  (их встраивает `include_bytes!`). `<[u8]>::to_vec` копирует их в `Vec<u8>`.

## Приёмы из этапа 6a
- `#[serde(flatten)] sections: HashMap<String, Value>` (`paimon/backup/backup.rs`) — «все остальные ключи JSON»
  собираются в словарь; нужные разделы берутся из него по имени.
- `#[serde(rename = "type")]` — поле JSON называется как ключевое слово Rust (`type`), а в коде — `kind`.
- Структура с временем жизни `RepeatDetector<'a>` хранит ссылки на строки молитв (`&'a str`) без копирования.
- `type PullKey<'a> = (&'a str, &'a str, &'a str);` — псевдоним типа делает код читаемее.
- `#[serde(skip)]` (`ImportSummary::item_ids`) — поле есть в Rust, но не передаётся в интерфейс.
- `fold` — свёртка итератора в одно значение (словарь отметок в `paimon_export_real.rs`).

## Тесты
- Тесты подключаются из отдельного файла: `#[cfg(test)] #[path = "game.tests.rs"] mod tests;` в конце `game/game.rs`.
  Атрибут `#[cfg(test)]` означает, что модуль компилируется только при `cargo test`, поэтому в `.exe` тесты не попадают.
  `#[test]` помечает тестовую функцию.
- Тесты — дочерний модуль, поэтому `use super::*;` даёт им доступ даже к приватным функциям и константам родителя.
- Тестовые заглушки реализуют те же трейты (`InMemoryRepository` в `settings_service/settings_service.tests.rs`).

## Атрибуты уровня крейта
- `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` в `main.rs` убирает окно консоли в релизной сборке.

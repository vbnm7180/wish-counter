## Детали этапов

### Этап 2. Домен молитв ✅ (2026-11-15)
- Сущности `Wish`, `Rarity`, `ItemKind`, `BannerCode`, `WishTime`; пулы баннеров с общим счётчиком (`PoolDefinition`).
- `PityTracker`: счётчики 5★/4★, номер молитвы по гаранту, 50/50, серия проигрышей, Capturing Radiance.
- `StatisticsService` + команда `get_game_statistics`: карточки баннеров, итоги по игре, примогемы.
- Vitest подключён раньше плана: тесты форматирования, подстановки параметров, логики статуса 50/50.
- Правила и согласованные решения — в [genshin-rules.md](genshin-rules.md).

### Этап 3. SQLite ✅ (2026-11-15)
- rusqlite с опцией `bundled`: SQLite встроена в .exe (ADR-015).
- Файл `data/wish-counter.sqlite`, режим WAL, свои миграции через `PRAGMA user_version`.
- Таблица `wishes` (миграция 0001), уникальность `(game_id, wish_id)`, индекс `(game_id, wish_time, row_id)`.
- `SqliteWishRepository`: `list_wishes` (хронологически) и `add_wishes` (транзакция, дубликаты пропускаются).
- Сквозной тест `crates/app-desktop/tests/statistics_end_to_end.rs`.
- Настройки остаются в `settings.json`.

### Этап 4. Справочные данные 🔄

**Решения владельца (2026-11-15):**
- источник — данные Paimon.moe (автор обновляет их вручную в день баннера; у HoYoverse нет публичного API расписания);
- сервер игрока (Америка/Европа/Азия/...) выбирается вручную или читается из JSON Paimon.moe — время баннеров
  пересчитывается так же, как в Paimon.moe (вариант «Б»);
- картинки скачиваются при первом показе и хранятся в `data/cache/images`; при импорте истории
  докачиваются картинки всех её предметов (кнопка «Скачать все» не нужна);
- обновление справочника: автоматически при запуске (не чаще раза в сутки) + кнопка;
- шанс нужного 4★ делается в 4a-2.

| Шаг | Содержание | Статус |

| 4a-2 | Сервер игрока, `FeaturedLookup` по расписанию (исход 50/50), шанс нужного 4★ | ✅ |

### Этап 7. Импорт из игры
- Чтение `output_log.txt` → путь к игре → `webCaches/<версия>/Cache/Cache_Data/data_2`
  → ссылка с `authkey` → API истории молитв с паузами между запросами.
- `authkey` не логируется, не сохраняется на диск и скрывается в интерфейсе.
- Подробнее — в [security.md](security.md).

# Безопасность

Документ пополняется на каждом этапе. Полный аудит — этап 9.

## Принципы

1. **Минимальные права интерфейса.** Окну выдано только `core:default`
   (`crates/app-desktop/capabilities/default.json`). Доступа к файлам, сети и запуску
   программ у JavaScript нет. Всё это делает Rust-код через явные команды.
2. **Строгий CSP** (`tauri.conf.json`): скрипты только из самого приложения,
   картинки — из приложения, `asset:` и `data:`. Загрузка внешних скриптов запрещена.
3. **Проверка входных данных на границе.** Данные из интерфейса и файлов проверяются типами домена
   (пример — `ThemeId::parse`), поэтому некорректные значения отклоняются ещё до бизнес-логики.
4. **Без `unsafe`**: `unsafe_code = "forbid"` для всего workspace.
5. **Секреты не попадают в логи.** `authkey` и подобные значения не логируются и не сохраняются (этап 7).
6. **Атомарная запись файлов**, чтобы сбой не портил данные. В базе — транзакции и журнал WAL.
7. **SQL только с параметрами** (`?1`, `params![]`). Данные никогда не подставляются в текст запроса,
   поэтому SQL-инъекция невозможна.
8. **Проверка данных из базы:** строки таблицы проходят проверку доменных типов (`WishTime::parse`, `Rarity::try_from`).
   Испорченный файл даёт ошибку `Corrupted`, а не панику.
9. **Скачанные данные не выполняются.** Файлы Paimon.moe — JavaScript, но они разбираются как данные
   (свой разборщик, ограничение вложенности). Сетевые запросы — только HTTPS к GitHub, без редиректов,
   с лимитами (ADR-021).

## Соблюдение пользовательского соглашения игр

| Способ получения истории | Решение |
|---|---|
| Ручной ввод, импорт файлов Paimon.moe / UIGF | ✅ Безопасно |
| Ссылка из веб-кэша игры (`data_2`) + запросы к API истории, который открывает сама игра | 🟡 Неофициальный способ: игра не модифицируется, файлы только читаются. Так работают Paimon.moe и аналоги |
| Перехват трафика (прокси, сниффер) | ❌ Не используется |
| Чтение памяти процесса, инъекции, модификация клиента | ❌ Не используется: прямое нарушение соглашения |

Для API истории: паузы между запросами, без параллельной нагрузки, только данные текущего пользователя.
